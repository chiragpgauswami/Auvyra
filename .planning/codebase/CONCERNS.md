# Codebase Concerns

**Analysis Date:** 2026-09-10

## Tech Debt

- **Monolithic & Primitive Media Matching:** In `backend/app/video/pipeline.py` (L57), search terms are generated by naive string splitting on the topic name (`[word for word in request.topic.split() if len(word) > 3]`) rather than semantic scene analysis. This query is fired globally across the whole video duration instead of per narrative beat.
- **Redundant Encoding Passes with MoviePy:** In `backend/app/video/composition/assembler.py` (L76-85), individual video clips are sequentially re-encoded to temporary files via MoviePy 2.x software rendering (`libx264`), then concatenated using FFmpeg concat demuxer, before being re-encoded a third time during final audio/subtitle overlay in `backend/app/video/composition/overlay.py`. This induces unnecessary CPU thrashing and disk I/O.
- **MoviePy Subtitle TextClip Inefficiency:** In `backend/app/video/composition/overlay.py` (L47-79), subtitles are rendered by instantiating individual `TextClip` objects for each subtitle line and combining them into a single `CompositeVideoClip`. This is significantly slower and more memory-intensive than native FFmpeg subtitle burn-in (`-vf "subtitles=..."`).
- **In-Memory Ephemeral Fernet Encryption Fallback:** In `backend/app/config.py` (L158-166), if `FERNET_ENCRYPTION_KEY` is not provided or set to defaults in development/test, a random key is generated in memory via `Fernet.generate_key()`. When multiple worker processes start or the server restarts, previously encrypted OAuth tokens in MongoDB become un-decryptable (`InvalidToken`), breaking channel integrations.
- **Hardcoded Ollama Client Timeout:** In `backend/app/ai/gateway.py` (L62), the `AsyncOpenAI` client hardcodes `timeout=30.0`, completely bypassing the configurable `settings.OLLAMA_TIMEOUT_SECONDS` (defaulting to 60.0s in `backend/app/config.py`).
- **Duplicate Repository Aliases:** The codebase contains redundant single/plural repository modules (e.g. `backend/app/repositories/channel.py` re-exporting `backend/app/repositories/channels.py`, `backend/app/repositories/job.py` for `jobs.py`, and `backend/app/repositories/video.py` for `videos.py`).

## Known Issues & Gaps

- **Missing Per-Scene Visual Storyboard Engine:** As identified in `docs/AUVYRA_IMPLEMENTATION_AUDIT.md`, `backend/app/video/storyboard.py` is absent. Narration is not parsed into 2–5 second scenes with Ollama-derived visual queries, duration boundaries, and text overlay cues.
- **Stock Video Selection & Smart-Cropping Gap:** `backend/app/video/media/pexels_provider.py` (L23-53) strictly filters Pexels API queries by `aspect_ratio.name`. If native 9:16 portrait stock videos are unavailable for a specific query, it returns empty rather than downloading high-definition landscape (16:9) clips and applying intelligent 9:16 center-cropping.
- **Silent Degradation to Local Gradients:** When stock search returns empty, `backend/app/video/pipeline.py` (L72-82) falls back to `backend/app/video/media/local_provider.py`, resulting in static synthetic color gradients and failing the required 70–90% stock footage timeline coverage.
- **Dormant Autopilot Subsystem:** `backend/app/models/channel.py` only defines an unused boolean flag `autopilot_enabled`. No autonomous loop orchestrator (`AutopilotService`), scheduled runner (`backend/app/workers/autopilot_worker.py`), or mode configuration (`OFF`, `ASSISTED`, `FULL_AUTOPILOT`) exists.
- **Channel Brain Onboarding Missing:** `backend/app/models/channel.py` only retains basic `ChannelMemory` lists (`best_topics`, `weak_topics`, `audience_insights`). The comprehensive `ChannelBrain` model (positioning, pillars, hook archetypes, winning/losing patterns, tone, learned heuristics) and dedicated onboarding flow (`POST /api/channels/{id}/onboard`) are not implemented.
- **Missing OAuth Token Refresh Mechanism:** `backend/app/services/publishing_service.py` (L60-69) and `backend/app/api/channels.py` (L108-115) decrypt `access_token_encrypted` directly. Neither service checks token expiration (`token_expires_at`) nor uses `refresh_token_encrypted` against Google's OAuth endpoint. Consequently, after 60 minutes, all automated YouTube publishing and analytics calls fail with HTTP 401 until the user manually reconnects.

## Security Considerations

- **Unauthenticated Video Streaming & Download Endpoints:**
  - `GET /api/videos/{video_id}/stream` in `backend/app/api/videos.py` (L92) lacks authentication dependencies (`require_auth`).
  - `GET /api/videos/{video_id}/download` in `backend/app/api/videos.py` (L152) lacks authentication dependencies (`require_auth`).
  - Any external request with a valid or guessed MongoDB `ObjectId` can stream or download rendered media files.
- **Tenant Isolation Bypass on Media Lookups:** In `backend/app/api/videos.py` (L94, L154), `video_repo.find_by_id(video_id)` is invoked without passing `user_id`. Tenant isolation is not enforced on video streaming or file retrieval.
- **Arbitrary File Streaming / Path Traversal Risk:** In `backend/app/api/videos.py` (L105-149, L164-171), `file_path` retrieved from the database document is directly passed to `open(file_path, "rb")` and `FileResponse(file_path)` without verifying that it resolves within `settings.MEDIA_ROOT`. A compromised or tampered database record could allow reading arbitrary server files.
- **Sensitive Secrets Present in Workspace Root:** Google OAuth client secret JSON (`client_secret_*.json`) is stored in the workspace root directory. While excluded in `.gitignore`, its existence on disk poses an exposure risk if directories are inadvertently packaged or backed up.
- **Channel Ownership Hijacking on OAuth Re-link:** In `backend/app/auth/service.py` (L307-315), if an existing channel with the same `youtube_channel_id` is linked during OAuth callback, it unconditionally updates `user_id` to the currently authenticating user without validating previous ownership.

## Performance Bottlenecks

- **FFmpeg & MoviePy CPU Saturation:** Because `backend/app/video/composition/assembler.py` and `backend/app/video/composition/overlay.py` rely heavily on MoviePy video file writers, clip concatenation and subtitle rendering saturate CPU threads via software x264 re-encoding. Without hardware encoder passthrough (`h264_videotoolbox`, `h264_nvenc`) and direct FFmpeg filtergraphs, 60-second video composition can take minutes per job.
- **Ollama Inference Latency on Local Models:** AI generation tasks in `backend/app/ai/gateway.py` (script generation, opportunity scoring, research) run synchronously against local Ollama models. On CPUs or entry-level GPUs, inferences take 15–45 seconds. With JSON retry loops (`max_retries=3`), requests can stall for over a minute.
- **Sequential Stock Footage Downloads:** In `backend/app/video/media/base.py` (L23-36), stock video assets are downloaded sequentially in an async `for` loop without concurrent worker pools or an `asyncio.gather` bounded semaphore, creating unnecessary network bottlenecks during multi-clip generation.

## Fragile Areas

- **Hardcoded Puppeteer Platform Executable:** In `scripts/real_user_acceptance_browser.js` (L15-16), Chrome executable path is hardcoded to macOS (`/Applications/Google Chrome.app/Contents/MacOS/Google Chrome`). This test runner crashes immediately on Linux CI servers, Docker environments, or Windows development machines.
- **Non-Deterministic Cache Keys via Built-in `hash()`:** In `backend/app/video/media/pexels_provider.py` (L69), media filenames are computed using Python's `hash(item.url)`. Due to Python's hash randomization (`PYTHONHASHSEED`), filenames change across interpreter restarts, invalidating local media caches and causing duplicate downloads.
- **Partial OAuth Scope Rejection Handling:** Google's OAuth consent flow permits users to uncheck individual granular permissions (e.g. `youtube.upload`). While `backend/app/youtube/scopes.py` detects missing scopes, `backend/app/auth/service.py` records the connection without preventing subsequent broken publishing jobs.

## Missing Critical Features

- **Autonomous Autopilot Worker:** `backend/app/workers/autopilot_worker.py` and `backend/app/services/autopilot_service.py` orchestrating the 21-step content cycle.
- **Dedicated AI Brain UI & Wizard:** Dedicated channel onboarding wizard (`POST /api/channels/{id}/onboard`) and frontend page `frontend/src/pages/Brain.tsx` for managing strategy and content pillars.
- **Autopilot Monitoring UI:** Dedicated interface `frontend/src/pages/Autopilot.tsx` for scheduling, cycle status, and approval controls.
- **Publishing Calendar & Queue Management:** `frontend/src/pages/Publishing.tsx` is currently an empty placeholder card lacking draft, schedule, and publish tracking.
- **Live Analytics API Integration:** `frontend/src/pages/Analytics.tsx` displays hardcoded zero metrics and unlinked placeholder chart states instead of consuming `/api/analytics` endpoints.
- **Standalone Media QA & Inspection CLI:** `scripts/inspect_video.py` and `scripts/test_pexels.py` for verifying video quality metrics, blank frames, and stock footage coverage percentage.

## Test Coverage Gaps

- **Stock Footage Timeline Coverage Regression:** Missing deterministic integration test `tests/video/test_stock_footage_regression.py` ensuring videos meet the $\ge 70\%$ stock footage threshold and do not fall back to synthetic gradients.
- **Cross-Tenant Authorization Tests:** Lack of automated tests verifying that `GET /api/videos/{id}/stream` and `GET /api/videos/{id}/download` reject unauthenticated or cross-tenant access.
- **OAuth Token Refresh Lifecycle Tests:** No tests validating automatic token refresh when YouTube access tokens expire after 1 hour.
- **Autopilot & Channel Brain Integration Tests:** Missing test suites for onboarding wizard validation, autonomous cycle progression, and multi-tenant channel memory isolation.
- **Frontend E2E Workflows:** Lack of automated browser tests for autonomous publishing workflows, onboarding wizards, and strategy updates across multiple environments.
